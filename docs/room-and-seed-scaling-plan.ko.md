# 방 만들기와 대규모 시드 풀 계획

## 방 만들기 방향

친구방은 방장이 게임 설정을 만든 뒤 링크나 방 코드로 초대하는 구조가 맞다. 방장은 아래 값만 고른다.

- 맵: 한국 전체, 서울, 강원, 경남, 제주 등
- 난이도: 상, 중, 하
- 라운드 수: 기본 5라운드
- 제한 시간: 기본 90초
- 로드뷰 이동 제한: 기본 5회

방에 들어온 플레이어는 같은 라운드, 같은 시작 로드뷰를 보고 각자 지도에 핀을 찍는다. 모두 제출했거나 제한 시간이 끝나면 정답, 각자 거리, 점수, 순위가 한 번에 공개된다.

## 방 상태 모델

- `lobby`: 방장이 설정을 고르고 참가자가 들어오는 상태
- `round_active`: 현재 라운드 진행 중
- `round_reveal`: 정답과 점수 공개
- `finished`: 최종 순위 공개

서버는 방 설정, 참가자, 제출 여부, 라운드 결과만 저장한다. 로드뷰 이미지는 계속 공식 SDK로만 표시한다.

## 시드 풀 1000개 목표

서울과 17개 시/도별로 승인된 출제 위치 1000개를 목표로 한다. 풀 자체는 `하 334 / 중 333 / 상 333`에 가깝게 유지하고, 사용자가 고르는 `하/중/상`은 이 풀에서 난이도 비율을 다르게 뽑는 게임 설정으로 처리한다.

좌표를 임의로 대량 생성하면 품질이 떨어지고 로드뷰가 없는 위치가 섞인다. 그래서 바로 코드에 가짜 좌표를 넣는 방식은 피해야 한다.

권장 파이프라인:

1. 후보 좌표 수집
   - 공개 지도/행정구역/도로망 데이터를 기준으로 후보 좌표를 만든다.
   - 로드뷰 이미지나 타일은 저장하지 않는다.
2. 자동 필터
   - 한국 경계 안 좌표만 허용한다.
   - 너무 유명한 POI, 관공서 정문, 역 광장, 관광지 정문은 제외 후보로 표시한다.
   - 지역, 도로 유형, 난이도 태그를 붙인다.
3. 로드뷰 존재 검증
   - 공식 SDK/API 흐름으로 근처 파노라마 존재 여부만 확인한다.
   - 파노라마 ID나 이미지를 영구 저장하지 않는다.
4. 사람 검수
   - 간판 하나로 정답이 드러나는 위치를 제외한다.
   - 하/중/상 난이도를 사람이 최종 확정한다.
5. 운영 반영
   - `approved` 상태의 좌표만 게임에 출제한다.

현재 구현된 보조 도구:

- 목표 수량: `data/seed-pipeline/region-targets.ko.json`
- 후보 생성: `npm run seed:candidates -- --region seoul --difficulty easy --limit 50`
- 목표 대비 감사: `npm run seed:audit`

`data/seed-pipeline/candidates`에 있는 후보 JSONL은 검수용이다. 실제 게임은 아직 `packages/shared/src/seeds.ts`에 들어간 좌표만 출제한다.

## 난이도 기준

- 하: 상점가, 중심지, 넓은 도로, 아파트 외곽처럼 지역 단서가 많은 위치
- 중: 생활도로, 주택가, 소도시 외곽, 항구 외곽처럼 단서는 있지만 바로 맞히기 어렵게 섞인 위치
- 상: 농로, 산간도로, 숲길, 밭담길처럼 단서가 적은 위치

상 난이도도 숲속만 나오면 재미가 떨어진다. 그래서 방 설정은 난이도별 비율을 다르게 적용한다.

- 하: 하 60%, 중 30%, 상 10%
- 중: 하 30%, 중 45%, 상 25%
- 상: 하 10%, 중 30%, 상 60%

이 방식이면 난이도를 올려도 완전히 비슷한 풍경만 반복되지 않는다.
